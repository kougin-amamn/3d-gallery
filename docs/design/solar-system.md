# 3D太陽系 設計書

Nov 4, 2026 · @NG

## 1. コンセプト

**「本物の暦で動く、暗く広い宇宙を旅する」体験を作る。** 開いた瞬間の日付どおりに惑星が並び、どの惑星へも滑らかに飛んでいけるビューアーを目指します。教材のような図ではなく、探査機から見た映像のような質感を優先します。

操作は「天体を選んで飛ぶ」「時間を進める・戻す」「スケールを切り替える」の3つに絞ります。

太陽系がチープに見える原因は、多くの場合「明るさ・大きさ・暗さ」の扱いにあります。次の対策を設計段階で組み込みます。

| チープに見える原因 | 設計上の対策 |
| --- | --- |
| 全天体が均一に明るく、影がない | 光源は太陽だけにし、夜側は暗く落とす。環境光は最小限にする |
| 太陽が黄色い球にしか見えない | 表面の粒状斑と周縁減光をシェーダーで描き、コロナとブルームで眩しさを出す |
| 惑星がただの色付き球 | 昼夜の境界(明暗境界線)、大気の縁の光、雲の層、海の鏡面反射、法線マップを入れる |
| 背景が真っ黒、または作り物の星 | 実際の星表から星の位置・明るさ・色を描き、天の川を淡く重ねる |
| 大きさと距離の比率が崩れて見える | 実寸と見やすい表示を切り替えられるようにし、どちらの状態かを画面に明示する |
| 遠い惑星がちらつく、重なりが乱れる | 対数深度バッファと、カメラ中心の座標系で精度の問題を防ぐ |
| 輪郭がギザギザ、色が飽和する | HDR描画、トーンマッピング、MSAA、ミップマップ付きテクスチャで画質を底上げする |
| カメラ移動が瞬間移動で酔う | 距離に応じて速度を変える放物線状の移動と、到着時の減速で滑らかにつなぐ |

## 2. 技術選定と実現方法

**アクアリウムと同じく、Three.js r170をビルドなしで同梱し、ESモジュールとimportmapで動かします。** 太陽系で特有の難所は「距離の幅」と「明るさの幅」です。この2点を最初から仕組みで解決します。

| 項目 | 採用 | 理由 |
| --- | --- | --- |
| 描画 | WebGL2 + 対数深度バッファ | 数千kmの衛星から数十億kmの海王星までを、ちらつかずに同じ画面に描ける |
| 座標の精度 | カメラ中心の座標系(毎フレーム、注目天体を原点に置き直す) | 32bit浮動小数で遠方の座標が震える問題を防ぐ。天体の位置自体は64bit(JSの数値)で計算する |
| 明るさ | HDR描画 + ACESトーンマッピング + ブルーム | 太陽の眩しさと、夜側の暗さを同じ画面で破綻させない |
| 惑星の位置 | JPLの近似軌道要素からケプラー方程式で計算 | 1800〜2050年の範囲で十分な精度があり、外部APIなしで任意の日時を計算できる |
| 衛星の位置 | 平均軌道要素による円・楕円軌道 | 見た目の正しさは十分。高精度が要る場合は後で差し替えられるよう計算部を分離する |
| 星空 | イェール輝星星表(約9,100星)をJSONに変換し点で描画 | 実在の星座が正しい位置・色・明るさで見える |
| 惑星の質感 | 写真ベースのテクスチャ(CC BY 4.0) + 独自シェーダー | 大気・雲・昼夜・環の影は既製マテリアルでは出ないため |
| 大量の小天体 | InstancedMesh / Points | 小惑星帯の数千個を1回の描画で済ませる |
| 調整UI | lil-gui(?devのときだけ) | 露出、大気、ブルームなどをその場で追い込むため |

軌道要素は [JPLの近似位置ページ](https://ssd.jpl.nasa.gov/planets/approx_pos.html) の表1(1800〜2050年)を使い、範囲外は表2a・2b(紀元前3000年〜3000年)に切り替えます。誤差は水星で15秒角、土星でも10分角程度で、画面上の見た目には影響しません。

## 3. スケールと時間

**表示は「見やすい」と「実寸」の2モードを用意し、切替は数秒かけて滑らかに補間します。** 実寸では地球が太陽から大きさの約12,000倍離れているため、全体を見ると惑星は点にしか見えません。内部の計算は常に実寸(km)で行い、表示だけを変換します。

| 項目 | 見やすい表示(初期) | 実寸表示 |
| --- | --- | --- |
| 軌道半径 | 対数に近い圧縮(外惑星ほど詰める) | 実際の距離 |
| 天体の大きさ | 最小表示径を保証し、大きさの順序は保つ | 実際の大きさ |
| 衛星の距離 | 母惑星の表示径に合わせて圧縮 | 実際の距離 |
| 遠くの天体 | ラベルと光点で位置を示す | 同左(これがないと何も見えない) |

画面の隅には常に「見やすい表示(距離と大きさは実際と異なります)」のようにモードを明示し、誤解を防ぎます。

**時間は開いた瞬間の現在時刻から始めます。** 速度は「停止・実時間・1時間/秒・1日/秒・1週間/秒・1か月/秒・1年/秒」の段階で切り替え、逆再生もできます。日付を直接入力して、過去や未来の配置へ飛べるようにします。

自転は各天体の自転周期と自転軸の向き(IAUの北極方向)で計算します。地球は日本が夜なら日本側が暗く見えるよう、時刻と向きを合わせます。対象は太陽、8惑星、主な衛星(月、ガリレオ衛星4つ、タイタン)、冥王星とし、全て `data/bodies.json` で管理します。

## 4. 3Dシーン設計

**光源は太陽ひとつ。各天体は「昼側・夜側・大気の縁」の3つが正しく見えることを品質の基準にします。** 特に地球を主役として最も作り込みます。

| 要素 | 表現手法 | 品質のポイント |
| --- | --- | --- |
| 太陽 | 粒状斑のノイズシェーダー + 周縁減光 + コロナの板 + ブルーム | 中心は白に近く、縁ほど橙色で暗い。表面はゆっくり泡立つ |
| 地球 | 昼の色 + 夜の都市光 + 雲 + 海の鏡面反射 + 大気 | 明暗境界線は夕焼け色に。雲は別の球で少し速く回し、地表に影を落とす |
| 大気 | 视線と光の角度から求める簡易散乱シェーダー | 地球は青、火星は薄い赤茶、金星は黄白。太陽の反対側でも縁が薄く光る |
| 岩石惑星・月 | 色 + 法線マップ | 光が横から当たる境界付近でクレーターの凹凸が浮き出る |
| ガス惑星 | 色 + 帯のゆらぎを加えるシェーダー | 木星の帯は緯度ごとにわずかに速さを変えて流す |
| 土星の環 | 半径方向の色・透過率テクスチャ | 環に土星本体の影が落ち、本体にも環の影が落ちる(ここが絶対に必要) |
| 小惑星帯・カイパーベルト | 大量の小さな点を実際の軌道分布で配置 | 必要以上に濃くしない。実際はほぼ空っぽであることを保つ |
| 星空 | 輝星星表の点 + 天の川の淡い背景 | 明るさと色温度は等級とB-V色指数から計算。天の川は惑星より常に暗く |
| 軌道線 | 細い線。天体の後ろほど薄くなる | 惑星に寄ると自動で消え、景色を邪魔しない |
| 光学的な効果 | レンズフレア(弱)、露出の自動調整 | 太陽を見ると周りが暗くなり、惑星の夜側を見ると暗い星が浮かぶ |

各天体は距離に応じて球の分割数とテクスチャの解像度を切り替え、遠い天体は光点として描きます。高解像度テクスチャ(4K〜8K)はその天体に近づいてから読み込み、最初の表示を速くします。

## 5. デザインとUI

**テーマは「探査機の航法室」。画面の9割は宇宙そのものにし、UIは細い線と小さな文字だけで組みます。** 色は宇宙の暗さを壊さないよう、彩度の低い寒色を地にし、アクセントは太陽の暖色を少量だけ使います。色は `data/theme.json` で管理します(下は初期案)。

| 役割 | 色 | 使いどころ |
| --- | --- | --- |
| 宇宙の地 | #03050A | 背景。純黒にしない |
| UIの文字 | #D8E1EA | ラベル、パネルの本文 |
| 控えめな文字・線 | #6F7C8C | 軌道線、補足情報、区切り線 |
| アクセント | #FFB46B | 選択中の天体、現在の時間、ボタンの押下状態 |
| パネルの地 | rgba(10, 16, 26, 0.55) + 背景ぼかし | 情報パネルと操作バー |

- **文字:** 数値は等幅数字で揃える。見出しは字間を広げた英字ラベル、本文は日本語。天体名は日本語と英語を併記する。
- **ラベル:** 天体の横に名前を出し、重なったら小さい天体の方を隠す。寄った天体のラベルは消す。
- **情報パネル:** 選択中の天体について、太陽からの距離、地球からの距離、光の到達時間、直径、公転・自転周期、表面温度を表示する。距離は時間に合わせて実際に変わる。
- **操作バー(下部):** 天体の選択、時間の速度と日付、スケール切替、軌道線・ラベルの表示、画質。何もしないと数秒で薄くなる。
- **カメラ演出:** 天体を選ぶと、現在地から一度引いてから寄る弧を描いて飛ぶ。移動時間は距離の対数に比例させ(2〜5秒)、到着時は天体の昼側が斜めから見える角度で止まる。放置すると天体の周りをゆっくり回る。
- **キー操作:** 0〜9で天体を選択、スペースで時間の一時停止、\[ \] で速度変更。

## 6. ソース管理

**アクアリウムと同じ構成方針で、天体の数値・色・画質はすべてJSONに出します。** https配信を前提にし、`file://` での直接起動は対象外とします。

```text
solar-system/
├─ index.html              importmapと起動のみ
├─ src/
│  ├─ main.js              初期化とメインループ
│  ├─ core/                renderer, camera(飛行演出), quality, loader, time
│  ├─ astro/               kepler(軌道計算), rotation(自転), scale(表示変換)
│  ├─ bodies/              sun, planet, earth, rings, atmosphere, moons
│  ├─ sky/                 stars, milkyway, belts
│  ├─ post/                composer(ブルーム、露出、フレア)
│  ├─ shaders/             *.glsl
│  └─ ui/                  hud, panel, labels, timebar
├─ data/
│  ├─ bodies.json          天体の大きさ・軌道要素・自転・表示設定
│  ├─ stars.json           輝星星表を変換したもの(赤経・赤緯・等級・色)
│  ├─ theme.json           UIの色と文字
│  └─ quality.json         low / medium / high の設定
├─ assets/textures/         2K(標準) と 4K〜8K(近づいたとき)
├─ tools/                   星表などをJSONに変換するスクリプト(公開物には含めない)
├─ vendor/three/           固定バージョンのThree.js
└─ docs/                    この設計書、比較用スクリーンショット
```

- **データ管理:** 天体を足すときは `bodies.json` に1件追加するだけにする。読み込み時に必須項目と単位(km、度、日)を検証する。
- **計算の検証:** `astro/` は描画に依存しない純粋な関数にし、NodeでJPL Horizonsの値と照合するテストを置く。
- **テクスチャ:** 出典とライセンスを `assets/LICENSES.md` に記録し、CC BYのものは画面内のクレジットにも表示する。
- **Git運用:** `main` は常に動く状態を保ち、マイルストーンごとにタグを打つ。大きなテクスチャはGit LFSに入れるか、別の配信先に置く。

## 7. 品質向上のための追加提案

**最も効果が大きいのは、最初に「太陽に照らされた地球と月」だけを写真のように仕上げることです。** 地球は人が写真を見慣れているので、ここが本物らしければ全体が本物に見えます。

1. **地球の垂直スライスを先に作る。** 昼夜の境界、都市光、雲の影、大気の縁、海の反射を仕上げ、納得できてから他の天体へ広げる。
2. **実際の写真と並べて比べる。** NASAの公開写真(アポロや探査機の画像)を参照にし、明るさと色を合わせる。参照は自分用で、画面には使わない。
3. **実機で測る。** 作業環境ではGPUの実速度が測れないため、各マイルストーンで手元のPCとスマホのフレームレートを `?dev` の表示で確認してもらう。
4. **軌道計算をテストする。** 特定の日時(例: 2026年1月1日)の惑星位置をJPL Horizonsの値と比べ、誤差が許容内であることを自動で確認する。日食・月食の日に影が重なるかも目で確かめる。
5. **スクリーンショットで前後比較する。** 地球・土星・太陽系全体の3つの定点カメラを決め、変更ごとに同じ画を保存する。
6. **テクスチャを段階的に読み込む。** 最初は小さな画像ですぐ表示し、寄った天体だけ高解像度に差し替える。KTX2圧縮で通信量とメモリを抑える。
7. **「今日の空」を入口にする(任意)。** 起動時に今日見える惑星や、近い天文現象(会合、衝など)を小さく案内し、飛べるようにする。
8. **音を足す(任意)。** 低い環境音と移動時の風切り音を、ミュートできる形で追加する。

注意点として、こちらの作業環境からは外部サイトの画像を直接ダウンロードできない場合があります。そのときは、手続き生成のテクスチャで先に完成させ、後から写真テクスチャを置くだけで差し替わる作りにします。写真テクスチャの候補は [Solar System Scopeのテクスチャ](https://www.solarsystemscope.com/textures)(CC BY 4.0、[ライセンス表記](https://doc.qt.io/qt-6/qt3d-attribution-solar-system-scope.html))です。

## 8. 品質基準とロードマップ

**5つのフェーズで進め、各段階の完成条件(ゲート)を満たしてから次へ進みます。** 下の数値は初期の目標値で、実機で測って見直します。

| 項目 | 目標(high) | 目標(low) |
| --- | --- | --- |
| フレームレート | 60fps | 30fps以上 |
| 描画の解像度倍率の上限 | 2.0 | 1.0 |
| 初回表示までの時間 | 3秒以内 | 5秒以内 |
| 初回に読み込むデータ | 15MB以内 | 8MB以内 |
| テクスチャ解像度(寄ったとき) | 8K | 2K |
| 星の数 | 約9,100(輝星星表の全部) | 6等星まで |
| 惑星位置の誤差(1800〜2050年) | JPLの表の公称誤差以内 | 同左 |

## 変更履歴(設計書の公開後に決めたこと)

### v0.2(2026-11-04)

- 名前を「太陽系ビューア」に決定(「航法室」は分かりにくいため使わない)
- 太陽: 一部のGPUで真っ黒になったため、重い表面シェーダーを毎フレーム計算する方式をやめ、模様をテクスチャに焼き込んでから流れ(フローマップ)で動かす方式にした。失敗時は簡易な質感に切り替える。紅炎(プロミネンス)をコロナのシェーダーに追加
- 惑星の夜側: 真っ暗で表面が見えないのはもったいないため、暗いまま表面が見える程度に環境光を足す
- 軌道線: 目立ちすぎたため細く・薄くする
- 露出の自動調整は実時間で追従し、瞬間移動のときだけ即座に合わせる
