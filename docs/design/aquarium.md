# 3Dアクアリウム 設計書

Nov 2, 2026 · @NG

## 1. コンセプト

**「部屋に置いて、ただ眺め続けられる静かな水槽」を作る。** 操作して遊ぶゲームではなく、光・水・生き物の質感だけで見入ってしまう環境映像(アンビエント)を目指します。インタラクションは餌やり・視点移動・時間帯切替の3つに絞ります。

前回「チープ」になった原因は、多くの場合モデルの数や派手さではなく、**水中らしさを作る要素の不足**です。次の表の対策を設計段階から組み込みます。

| チープに見える原因 | 設計上の対策 |
| --- | --- |
| 青い背景に物を置いただけで、水の気配がない | 深度に応じた色の吸収(遠いほど青緑に沈む)、指数フォグ、浮遊粒子(マリンスノー)を常時入れる |
| 光が均一で影が弱い | 水面からのゴッドレイ(光の筋)、底面のコースティクス(光の揺らぎ)、方向性のある主光源を置く |
| 魚が板ポリや硬い動きで機械的 | 頂点シェーダーで体をくねらせ、速度に応じて尾の振幅を変える。種ごとに挙動を変える |
| 素材がのっぺりしている | PBRマテリアル、環境マップによる反射、法線マップ、AOのベイクで質感の密度を出す |
| 配置が均等で人工的 | 前景・中景・遠景の3層に分け、ノイズで不規則に分布させる。構図の「抜け」と密度の差を作る |
| 色がちぐはぐで派手 | パレットを先に固定し、トーンマッピングとブルームは控えめにする |
| 静止している要素が多い | 水草の揺れ、気泡、砂の舞い上がり、魚の個体差のある遊泳で常に微動させる |

## 2. 技術選定と実現方法

**Three.js(ES Modules)をビルドなしで使う構成を採用します。** 素のWebGLよりマテリアル、glTF読み込み、ポストプロセスが揃っており、品質の作り込みに時間を使えます。https配信を前提にするため、JSONやglTFは `fetch` で読み込みます。

| 項目 | 採用 | 理由 |
| --- | --- | --- |
| 描画API | WebGL2(WebGLRenderer) | 対応環境が広い。WebGPUは後から試せるよう描画層を分離しておく |
| 読み込み方式 | ネイティブESM + importmap | ビルド工程が不要で、静的ホスティングにそのまま置ける |
| Three.jsの配置 | `vendor/` に固定バージョンで同梱 | CDN障害や更新による挙動変化を避ける |
| 魚の大量描画 | InstancedMesh + 頂点シェーダー | 数十〜百匹規模でもドローコールを抑えつつ体のうねりを表現できる |
| 水中表現 | 独自シェーダー(色の吸収、フォグ、コースティクス) | 水らしさの中核なので既製品に頼らず調整できるようにする |
| 光の筋 | 加算ブレンドの半透明板 + 揺らぎ | 軽量で見栄えが安定する。重ければポスト処理の放射ブラーに切替 |
| ポストプロセス | EffectComposer(Bloom弱、被写界深度弱、ビネット) | 質感の底上げ。強度はJSONで管理し品質設定で段階的にOFFにできる |
| 3Dアセット | glTF(meshopt圧縮) + KTX2テクスチャ | 読み込みとメモリを軽くする |
| 調整UI | lil-gui(開発時のみ) | 色・光・フォグをリアルタイムに追い込むため |

レンダリングの流れは「ワールド更新(魚・水草・泡) → 水中シェーダー付きの本描画 → ポストプロセス → 画面」です。品質プリセット(low / medium / high)で解像度倍率、粒子数、ポスト処理、魚の数を切り替えます。

## 3. 3Dシーン設計

**水槽は「ガラス箱の中」ではなく、奥行きのある水中の一場面として見せます。** 手前から奥へ前景・中景・遠景の3層を置き、遠景ほど霞ませて奥行きを作ります。

| 要素 | 表現手法 | 品質のポイント |
| --- | --- | --- |
| 水中ボリューム | 深度に応じた色の吸収 + 指数フォグ | 浅部は明るい青緑、深部は暗い青。赤は先に減衰させる |
| 水面 | 下から見た面として描画。ノイズで揺らす | 全反射のような縁の明るさと、ゆっくりした波紋 |
| 主光源 | 上方からの方向光 + 弱い環境光 | 影は柔らかく。光の筋(ゴッドレイ)で方向を可視化 |
| コースティクス | 揺らぐ網目模様を底面・岩・魚に投影 | 魚にも当てると同じ水の中にいる説得力が出る |
| 底砂 | 高さのある地形メッシュ + 砂テクスチャ | 凹凸と流れの跡、岩の周りの溜まりで人工感を消す |
| 岩・流木 | glTFまたは手続き生成 + 法線マップ + AO | 大・中・小を不規則に配置し、苔や汚れで色を散らす |
| 水草 | 帯状メッシュのインスタンス + 頂点シェーダーで揺れ | 根元は固く先端ほど大きく揺らす。株ごとに位相をずらす |
| 魚 | InstancedMesh + 体のうねりシェーダー | 側面の反射と腹の色の違い、薄い半透明のヒレ |
| 気泡 | ポイントスプライト | 上昇に従い大きくなり、水面で消える。数は控えめ |
| 浮遊粒子 | 小さな粒を大量にゆっくり漂わせる | 光の筋の中だけ明るく見えるようにする |
| ガラス・外枠 | 薄い反射と縁の厚み | 派手にせず、水槽の外の部屋の気配は微かに映す程度にする |

構図は、画面の1/3に視線を集める主役の岩組み・水草群、残りに余白(抜け)を置き、魚はそこを横切るようにします。

## 4. 生き物の挙動設計

**魚の動きは、群れの法則(Boids)に「層・壁・餌・個体差」を重ねて作ります。** 全員が同じ動きをしないことが、生きている感じの最大の要因です。

Boidsの基本3則は、分離(ぶつからない)・整列(向きを揃える)・結合(群れの中心へ寄る)です。ここに次の力を加えます。

- 壁・底・水面の回避(滑らかに避けて反転しない)
- 好みの深さ(種ごとに泳ぐ層を持つ)
- 餌への誘引(餌やり時だけ強くなる)
- 個体ごとの気まぐれ(ノイズで速度と向きを微かに揺らす)

| 種類のタイプ | 動き | 泳ぐ層 | 数の目安 |
| --- | --- | --- | --- |
| 小型の群泳魚 | 密な群れ、素早い方向転換 | 中層 | 30〜60 |
| 中型の魚 | 2〜3匹の緩い群れ、ゆったり泳ぐ | 中〜上層 | 5〜10 |
| 底生魚 | 底を這い、立ち止まる | 底 | 3〜6 |
| 主役の大型魚 | 単独で大きく旋回、画面を横切る | 中〜下層 | 1〜2 |

数は初期の目安で、実機のフレームレートを見て調整します。

遊泳アニメは、体軸に沿った波(頭は小さく尾は大きく)を頂点シェーダーで加えます。波の速さと振幅は実際の移動速度に連動させ、止まるときは尾を緩め、加速するときは大きく振ります。ヒレは別の位相で小さく動かします。

種の定義(色、大きさ、群れの係数、層、速度、数)は `data/species.json` に置き、コードを触らずに調整・追加できるようにします。

## 5. デザイン

**テーマは「夜明けの静かな水槽」。彩度を抑えた青緑を土台に、魚だけに暖色を少量使って視線を導きます。** 色は先に固定し、`data/palettes.json` で管理します(下の値は初期案です)。

| 役割 | 色 | 使いどころ |
| --- | --- | --- |
| 浅部の水 | #7FD8E0 | 水面付近、光の筋 |
| 深部の水 | #0B3A53 | 奥行き方向のフォグ、背景 |
| 底砂 | #D9C8A0 | 砂地、明るい面 |
| 水草 | #3F8F4A | 緑は彩度を抑え、先端だけ少し明るく |
| 魚のアクセント | #FF7A45 | 主役魚と小型魚の一部のみ。画面の5%以内 |

**時間帯プリセットは朝・昼・夜の3種類です。** 光の色温度、光の筋の強さ、フォグ濃度、環境光を切り替え、遷移はゆっくりフェードします。夜は光を落とし、水槽ライトの局所的な明かりと粒子を主役にします。

**UIは最小限にします。** 通常は何も表示せず、操作したときだけ下部にバーが出ます。

- 餌やり(ボタン1つ)
- 時間帯の切替
- 画質の切替(自動 / low / medium / high)
- 全画面表示

カメラは通常、ゆっくりした自動ドリー(わずかな前後と左右)で動かし、ドラッグすると視点を回せます。ズームと角度には制限を設け、水槽の外が見えないようにします。魚を選んで追従するモードは後のマイルストーンで追加します。

## 6. ソース管理

**ビルドなしの静的サイトとして、役割ごとにモジュールを分け、調整値はすべてJSONに出します。** コードを触らずに見た目を追い込めるのが目的です。https配信を前提にし、`file://` での直接起動は対象外とします。

```text
aquarium/
├─ index.html            importmapと起動のみ
├─ src/
│  ├─ main.js            初期化とメインループ
│  ├─ core/              renderer, camera, quality, loader
│  ├─ world/             tank, water, light, sand, rocks, plants
│  ├─ life/              boids, fish, bubbles, particles
│  ├─ post/              composer(ポストプロセス構成)
│  ├─ shaders/           *.glsl(fetchで読み込み)
│  └─ ui/                hud
├─ data/
│  ├─ species.json       魚・生き物の定義
│  ├─ palettes.json      色と時間帯プリセット
│  ├─ scene.json         配置、光、フォグ、カメラ
│  └─ quality.json       low / medium / high の設定
├─ assets/               models(glTF), textures(KTX2)
├─ vendor/three/         固定バージョンのThree.js
└─ docs/                 この設計書、メモ、スクリーンショット
```

- **データ管理:** 種、色、シーン、画質の値は `data/*.json` だけに置き、コードに埋め込みません。読み込み時に必須項目を検証し、足りなければ分かるエラーを出します。
- **モジュール方針:** 1ファイル1責務とし、`world/` と `life/` は描画APIに依存する部分を `core/` 経由に限定します(将来のWebGPU切替を楽にするため)。
- **Git運用:** `main` は常に動く状態を保ち、作業は `feature/*` ブランチで行います。マイルストーンごとにタグ(v0.1、v0.2 …)を打ちます。見た目の変更はスクリーンショットを `docs/shots/` に残して前後比較します。
- **アセット:** 自作またはライセンスが明確なものだけを使い、出典とライセンスを `assets/LICENSES.md` に記録します。

## 7. 品質向上のための追加提案

**最も効果が大きいのは、全体を作る前に「1匹の魚 + 水 + 光」だけを完成度の高い状態まで作ることです。** そこで見た目の基準を決め、あとは同じ基準を広げます。

1. **垂直スライスを先に作る。** 水の色、光の筋、コースティクス、魚1匹の質感を最初に仕上げ、納得できてから魚の数や環境を増やす。
2. **ムードボードを用意する。** 目指す水槽の写真を数枚集めて基準にする(自分用の参照として使い、そのまま模写はしない)。色と光の比較がぶれなくなる。
3. **調整UIで追い込む。** 開発中だけ色・フォグ・光の強さをスライダーで動かせるようにし、決まった値を `data/*.json` に書き戻す。
4. **スクリーンショットで前後比較する。** 同じ視点・同じ時間帯の画像を変更ごとに保存し、良くなったかを目で判断する。こちらの環境で画面を撮影できる場合は、それを使って確認しながら進める。
5. **アセットの質を上げる。** 魚はBlenderなどで制作したglTFを使い、AOのベイクと法線マップを入れる。難しい場合は手続き生成の魚から始め、主役魚だけ差し替える。
6. **画質の自動調整を入れる。** フレームレートが落ちたら解像度倍率やポスト処理を自動で下げ、低性能な端末でも破綻させない。
7. **音を足す(任意)。** 水中のこもった環境音と小さな泡の音を、ミュートできる形で追加する。没入感が上がる。
8. **「やらないこと」を決める。** 魚種や機能を欲張らず、写実性が足りない部分は構図と光で補う。

## 8. 品質基準とロードマップ

**5つのマイルストーンで進め、各段階の完成条件(ゲート)を満たしてから次へ進みます。** 下の数値は初期の目標値で、実機で測って見直します。

| 項目 | 目標(high) | 目標(low) |
| --- | --- | --- |
| フレームレート | 60fps | 30fps以上 |
| 描画の解像度倍率の上限 | 2.0 | 1.0 |
| ドローコール | 100以下 | 60以下 |
| 魚の数 | 約60 | 約20 |
| ポストプロセス | Bloom + 被写界深度 + ビネット | ビネットのみ |
| アセット総量(圧縮後) | 10MB以内 | 同左 |

## 変更履歴(設計書の公開後に決めたこと)

### v0.2 色の設計の見直し(2026-11-06)

v0.1 は青緑・緑・灰色ばかりで単調だった。原因と対策:

| 原因 | 対策 |
| --- | --- |
| 色の配分を決めていなかった | 地の色(水・水草の青緑)約6割、中間色(砂・岩・流木)約3割、差し色(オレンジ・赤)約1割と決める |
| 赤の吸収が海並みに強く、暖色が少し離れると灰色になる | 赤の吸収を本物の水槽(奥行き数十cm)相当に弱める(朝 0.048 / 昼 0.044 / 夜 0.08) |
| 魚の補助光に水の色をそのまま足していた | 明るさだけを主に足し、暖色が青緑にくすまないようにする |
| 主役が水の色と同じ明るさで埋もれる | 差し色を主役と手前に集める |
| 水草が一色 | 先端が赤い有茎草(ロタラ風)を奥の3か所に置く |

差し色の割り当て(淡水のまま。カクレクマノミは海水魚のため採用しない):

- エンゼル2匹のうち1匹をコイ・エンゼル(白地に橙の大きな斑と黒の細かな斑)
- グラミーをハニードワーフグラミー(橙金、喉から腹は濃紺、背びれの縁は黄)
- ネオンをカーディナルテトラ(赤い腹を頭から尾まで)
- チェリーシュリンプ18匹を流木と岩の上に(`scene.json` の `shrimp`)
- 流木を暖かい茶色に寄せる
